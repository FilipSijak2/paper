Implement the full real YOLO-based anomaly detection pipeline for my ROS 2 Raspberry Pi + Jetson Orin robot project.

Important architecture decision:

* Jetson Orin should perform the complete anomaly detection and evidence generation pipeline.
* Raspberry Pi should remain the main ROS 2 robot computer for navigation, SLAM, map, odometry, LiDAR and camera publishing.
* Jetson should NOT join the ROS 2 DDS network directly because this overloaded the Raspberry Pi in earlier tests.
* Communication between Raspberry Pi and Jetson should use rosbridge WebSocket.
* Foxglove should connect to Raspberry Pi through foxglove_bridge WebSocket.
* Jetson should publish only the necessary anomaly visualization topics back to Raspberry Pi through rosbridge so Foxglove can display them.
* Actual anomaly image files and map snapshot PNGs should be saved on Jetson, not on Raspberry Pi.

Context:

* Raspberry Pi 5 runs ROS 2, SLAM/Nav2, `/map`, `/tf`, `/tf_static`, `/odom`, `/scan` and camera topics.
* Raspberry Pi runs `rosbridge_server` on port `9090`.
* Raspberry Pi runs `foxglove_bridge` on port `8765`.
* Jetson Orin runs YOLO inference.
* For the first real test scenario, treat `bottle` as the anomaly object.
* YOLO may detect multiple classes internally, but only `bottle` should trigger an anomaly event for now.

Target architecture:

Raspberry Pi:

* Runs the main ROS 2 robot stack.
* Publishes compressed camera stream, for example `/camera/color/image/compressed`.
* Publishes `/map`.
* Publishes robot pose in map frame either through an existing topic such as `/amcl_pose` or through a new lightweight topic `/robot_pose_map`.
* Runs `rosbridge_server`.
* Runs `foxglove_bridge`.
* Does not run YOLO.
* Does not save anomaly camera images.
* Does not save anomaly map snapshot PNG files.
* Receives anomaly visualization topics from Jetson through rosbridge:

  * `/anomaly/events`
  * `/anomaly/markers`
  * `/anomaly/debug_image/compressed`
  * `/anomaly/map_snapshot/compressed`

Jetson Orin:

* Runs `jetson_yolo_rosbridge_client`.
* Connects to Raspberry Pi rosbridge WebSocket, for example `ws://raspberry.local:9090`.
* Subscribes to:

  * `/camera/color/image/compressed`
  * `/map`
  * `/robot_pose_map` or `/amcl_pose`
* Runs real YOLO inference on incoming compressed camera images.
* Detects `bottle` as the anomaly class.
* Saves original bottle detection images locally on Jetson.
* Saves annotated bottle detection images locally on Jetson.
* Computes or estimates anomaly position in map frame using robot pose and configured camera/distance assumptions.
* Generates and saves map snapshot PNG locally on Jetson with label `ANOMALY: bottle`.
* Publishes anomaly visualization topics back to Raspberry Pi through rosbridge:

  * `/anomaly/events`
  * `/anomaly/markers`
  * `/anomaly/debug_image/compressed`
  * `/anomaly/map_snapshot/compressed`

Required topics:

1. `/camera/color/image/compressed`

* Type: `sensor_msgs/CompressedImage`
* Publisher: Raspberry Pi camera pipeline
* Subscriber: Jetson through rosbridge
* Used for YOLO inference.
* Avoid raw camera images over rosbridge.

2. `/map`

* Type: `nav_msgs/OccupancyGrid`
* Publisher: Raspberry Pi SLAM/Nav2 stack
* Subscriber: Jetson through rosbridge
* Jetson should keep the latest map and use it for generating map snapshot PNGs.

3. `/robot_pose_map`

* Preferred type: `geometry_msgs/PoseStamped`
* Publisher: Raspberry Pi
* Subscriber: Jetson through rosbridge
* Contains robot pose in `map` frame.
* If this topic does not already exist, implement a small lightweight Raspberry Pi node that reads TF `map -> base_link` and publishes `/robot_pose_map` at low rate, for example 1 Hz.
* This node should be minimal and should not do any anomaly processing.

Alternative:

* If `/amcl_pose` is already available and reliable, Jetson can subscribe to `/amcl_pose` instead of `/robot_pose_map`.

4. `/anomaly/events`

* Type: `std_msgs/String`
* Publisher: Jetson through rosbridge
* Payload: JSON
* Used for Foxglove raw message visualization and event logging.

Example event:

```json
{
  "id": "anom_00042",
  "timestamp": "2026-06-16T14:22:31",
  "label": "bottle",
  "type": "semantic_object_anomaly",
  "confidence": 0.87,
  "status": "active",
  "ttl_sec": 180,
  "bbox_xyxy": [312, 210, 390, 420],
  "robot_pose_map": {
    "x": 1.52,
    "y": -0.48,
    "yaw": 1.31
  },
  "object_pose_map": {
    "x": 2.10,
    "y": -0.92,
    "z": 0.0
  },
  "jetson_files": {
    "original_image": "/home/jetson/anomaly_logs/images/original/anom_00042_bottle.jpg",
    "annotated_image": "/home/jetson/anomaly_logs/images/annotated/anom_00042_bottle.jpg",
    "map_snapshot": "/home/jetson/anomaly_logs/map_images/anom_00042_bottle_map.png",
    "event_log": "/home/jetson/anomaly_logs/events.jsonl"
  }
}
```

5. `/anomaly/markers`

* Type: `visualization_msgs/MarkerArray`
* Publisher: Jetson through rosbridge
* Visualized in Foxglove through Raspberry Pi foxglove_bridge.
* For each anomaly, publish:

  * one object marker at the estimated anomaly position in `map` frame
  * one `TEXT_VIEW_FACING` marker with text `ANOMALY: bottle`
* Markers should remain visible for 3 minutes.
* Use configurable TTL, default `180` seconds.
* Either:

  * set marker lifetime to 180 seconds
  * or republish active markers at 1 Hz and delete expired markers after TTL
* Prefer the robust approach: keep an active anomaly list on Jetson, republish markers at 1 Hz, and send DELETE markers after expiration.

6. `/anomaly/debug_image/compressed`

* Type: `sensor_msgs/CompressedImage`
* Publisher: Jetson through rosbridge
* Contains annotated YOLO image with bounding box, label and confidence.
* Used for Foxglove preview.
* The actual annotated image file should be saved locally on Jetson.

7. `/anomaly/map_snapshot/compressed`

* Type: `sensor_msgs/CompressedImage`
* Publisher: Jetson through rosbridge
* Contains generated map image with `ANOMALY: bottle` label.
* The actual PNG file should be saved locally on Jetson.

YOLO requirements:

* Implement real YOLO inference on Jetson.
* Use a pretrained YOLO model by default, preferably Ultralytics YOLOv8 nano.
* Default model should be `yolov8n.pt` unless a model path is configured.
* Use configurable model path.
* Use configurable confidence threshold, default `0.5`.
* Use configurable anomaly classes, but default should be:

```yaml
anomaly_classes:
  - bottle
```

* Ignore all non-bottle detections.
* Add simple cooldown/debounce so the same bottle does not generate events every frame.
* Default cooldown: 5 seconds.

Jetson local saving:

* Save all anomaly artifacts locally on Jetson.
* Default directories:

  * `/home/jetson/anomaly_logs/images/original/`
  * `/home/jetson/anomaly_logs/images/annotated/`
  * `/home/jetson/anomaly_logs/map_images/`
  * `/home/jetson/anomaly_logs/events.jsonl`
* Save:

  * original camera frame
  * annotated camera frame
  * map snapshot PNG with anomaly marker
  * JSON event log
* Do not copy image files to Raspberry Pi.

Anomaly localization on Jetson:

* Implement MVP localization first.
* Use latest robot pose in `map` frame from `/robot_pose_map` or `/amcl_pose`.
* Estimate anomaly position in front of robot using configurable distance, default 1.0 m or 1.5 m.
* Optionally improve angle using bbox center and configurable camera horizontal FOV.
* If `depth_m` is added later, use it as distance.
* Keep this modular so it can later be replaced with real depth projection.

Map snapshot generation on Jetson:

* Subscribe to `/map` and keep latest occupancy grid.
* Convert occupancy grid to image:

  * unknown = gray
  * free = white
  * occupied = black
* Convert anomaly `map` coordinates to image pixels using map origin and resolution:

  * `px = int((x - origin_x) / resolution)`
  * `py = int((y - origin_y) / resolution)`
  * invert y axis for image coordinates
* Draw marker/rectangle at anomaly position.
* Draw text label `ANOMALY: bottle`.
* Save PNG locally on Jetson.
* Publish compressed version to `/anomaly/map_snapshot/compressed`.

Foxglove:

* Foxglove should run on Jetson or laptop and connect to Raspberry Pi:

  * `ws://raspberry.local:8765`
* Jetson should not join DDS for Foxglove.
* Raspberry Pi foxglove_bridge should expose the normal robot topics and the anomaly topics that Jetson publishes through rosbridge.
* Foxglove should visualize:

  * `/map`
  * `/tf`
  * `/tf_static`
  * `/scan` or `/scan_filtered`
  * `/odom`
  * `/robot_pose_map` if available
  * `/anomaly/markers`
  * `/anomaly/events`
  * `/anomaly/debug_image/compressed`
  * `/anomaly/map_snapshot/compressed`
